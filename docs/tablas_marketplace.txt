MARKETPLACE DE ALOJAMIENTOS - INVERSIONES LR
Tablas de la base de datos (PostgreSQL 17)
==============================================================================

CONEXIÓN LOCAL
  Host: localhost   Puerto: 5432   Base: marketplace_db
  Usuario: marketplace   Clave: MarketplaceLR2026
  Crear la base: psql postgres -f docs/base_de_datos.sql
  Las tablas las crea el backend al arrancar (cd backend && ./mvnw spring-boot:run).

CÓMO LEER ESTE ARCHIVO
  columna_bd   TIPO   (nombreEnJSON)   notas
  - columna_bd: nombre en la base de datos (snake_case).
  - nombreEnJSON: nombre del campo como llega en las respuestas de la API (camelCase).
  - PK = llave primaria, FK = llave foránea, único = no se puede repetir.
  - Dinero en pesos colombianos (COP). Fechas como "2026-12-20"; fecha-hora como "2026-12-20T15:30:00".

TOTAL: 19 tablas

------------------------------------------------------------------------------
1. usuario   (entidad Usuario)
   Usuario registrado (huésped, anfitrión o administrador).
------------------------------------------------------------------------------
   id                 BIGINT        (id)                PK, autoincremental
   nombre             VARCHAR(120)  (nombre)            obligatorio
   correo             VARCHAR(150)  (correo)            obligatorio, único
   hash_contrasena    VARCHAR(255)  (nunca se envía)    obligatorio, clave cifrada con BCrypt
   rol                VARCHAR(15)   (rol)               obligatorio
   estado             VARCHAR(12)   (estado)            obligatorio
   telefono           VARCHAR(20)   (telefono)          opcional (HU-05)
   foto_url           VARCHAR(500)  (fotoUrl)           opcional (HU-05)
   intentos_fallidos  INTEGER       (intentosFallidos)  obligatorio
   bloqueado_hasta    TIMESTAMP     (bloqueadoHasta)    
   creado_en          TIMESTAMP     (creadoEn)          obligatorio
   Reglas (CHECK):
     - rol IN ('HUESPED','ANFITRION','ADMINISTRADOR')
     - estado IN ('ACTIVO','INACTIVO','RESTRINGIDO')
     - intentos_fallidos >= 0

------------------------------------------------------------------------------
2. notificacion   (entidad Notificacion)

------------------------------------------------------------------------------

10. periodo_disponibilidad   (entidad PeriodoDisponibilidad)
   Periodo del calendario de un alojamiento (HU-16 a HU-18). RESERVADO tiene reserva_id.
------------------------------------------------------------------------------

   reserva_id      BIGINT       (reservaId)      FK → reserva.id

------------------------------------------------------------------------------
12. reserva   (entidad Reserva)
   Reserva de un alojamiento hecha por un huésped.
------------------------------------------------------------------------------
   id               BIGINT         (id)              PK, autoincremental
   huesped_id       BIGINT         (huespedId)       obligatorio, FK → usuario.id
   alojamiento_id   BIGINT         (alojamientoId)   obligatorio, FK → alojamiento.id
   fecha_llegada    DATE           (fechaLlegada)    obligatorio
   fecha_salida     DATE           (fechaSalida)     obligatorio
   num_huespedes    INTEGER        (numHuespedes)    obligatorio
   noches           INTEGER        (noches)          obligatorio
   precio_base      NUMERIC(12,2)  (precioBase)      obligatorio
   tarifa_limpieza  NUMERIC(12,2)  (tarifaLimpieza)  obligatorio
   tarifa_servicio  NUMERIC(12,2)  (tarifaServicio)  obligatorio
   descuento        NUMERIC(12,2)  (descuento)       obligatorio
   total            NUMERIC(12,2)  (total)           obligatorio
   estado           VARCHAR(20)    (estado)          obligatorio
   requiere_revision BOOLEAN       (requiereRevision) true si su publicación fue bloqueada (HU-42)
   creada_en        TIMESTAMP      (creadaEn)        obligatorio
   Reglas (CHECK):
     - estado IN ('PENDIENTE_PAGO','CONFIRMADA','PAGO_FALLIDO','CANCELADA','COMPLETADA','EN_REVISION')
     - fecha_salida > fecha_llegada
     - num_huespedes > 0
     - noches > 0
     - precio_base >= 0 AND tarifa_limpieza >= 0 AND tarifa_servicio >= 0 AND descuento >= 0 AND total >= 0

RELACIONES PRINCIPALES
  usuario 1 ── * alojamiento            (alojamiento.anfitrion_id)
  usuario 1 ── * reporte_exportacion    (reporte_exportacion.admin_id)
  usuario 1 ── * reserva                (reserva.huesped_id)
  usuario 1 ── * notificacion
  politica_cancelacion 1 ── * alojamiento
  alojamiento * ── * servicio           (tabla puente alojamiento_servicio)
  alojamiento 1 ── * imagen
  alojamiento 1 ── * servicio_adicional
  alojamiento 1 ── * periodo_disponibilidad
  alojamiento 1 ── * reserva
  reserva * ── * servicio_adicional     (tabla puente reserva_servicio_adicional, guarda el precio cobrado)
  reserva 1 ── * pago
  reserva 1 ── 0..1 cancelacion
  reserva 1 ── 0..1 resena
  reserva 1 ── 0..1 periodo_disponibilidad RESERVADO (se crea al reservar y se borra al cancelar o si falla el pago)
  evento_auditoria: sin llaves foráneas a propósito (ADR-06), solo admite INSERT.

ESTADOS (para mostrar en el frontend)
  usuario.rol ................ HUESPED, ANFITRION, ADMINISTRADOR
  usuario.estado ............. ACTIVO, INACTIVO, RESTRINGIDO
  alojamiento.estado ......... BORRADOR → PENDIENTE_REVISION → ACTIVA ⇄ PAUSADA; BLOQUEADA (admin)
  alojamiento.modo_reserva ... INMEDIATA (paga al reservar), APROBACION (el anfitrión aprueba y luego se paga)
  alojamiento.tipo ........... CASA, APARTAMENTO, FINCA, CABANA, HABITACION, GLAMPING
  reserva.estado ............. EN_REVISION, PENDIENTE_PAGO, CONFIRMADA, PAGO_FALLIDO, CANCELADA, COMPLETADA
  periodo_disponibilidad ..... DISPONIBLE (el anfitrión abre fechas), BLOQUEADO (las cierra), RESERVADO (automático)
  pago.estado ................ APROBADO, RECHAZADO, DEVUELTO
  reporte_exportacion.estado . PENDIENTE → PROCESANDO → LISTO o ERROR
  politica_cancelacion.tipo .. FLEXIBLE (id 1), ESTRICTA (id 2)

DATOS QUE YA VIENEN AL ARRANCAR
  - Administrador: admin@marketplace.com / Admin2026*
  - Políticas: 1 Flexible, 2 Estricta
  - Servicios: 1 Wifi, 2 Parqueadero, 3 Piscina, 4 Cocina equipada, 5 Aire acondicionado,
               6 Lavadora, 7 Televisión, 8 Admite mascotas, 9 Zona BBQ, 10 Jacuzzi
  - Tarifas: TARIFA_SERVICIO_PORCENTAJE = 10, DESCUENTO_SEMANAL_PORCENTAJE = 5, NOCHES_DESCUENTO_SEMANAL = 7

NOTA PARA EL FRONTEND
  El frontend nunca habla con la base de datos: todo pasa por la API REST (http://localhost:8080).
  Las rutas, lo que hay que enviar y lo que responde cada una están en docs/GUIA_BACKEND.md
  y en la colección de Postman docs/Marketplace_LR.postman_collection.json.
  Con el backend corriendo también se ven en Swagger: http://localhost:8080/swagger-ui.html
  Las fotos se suben con POST /alojamientos/{id}/imagenes/archivo (multipart, campo "archivo")
  y se muestran con la URL que devuelve (GET /imagenes/{nombre}).
